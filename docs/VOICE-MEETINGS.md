# 语音输入与会议录制

输入框发送按钮旁有麦克风按钮：**按下即申请麦克风并采集，按住 350 毫秒确定为语音输入，识别结果逐步写入草稿，松开后确认尾句**。长按判定与后台启动期间的 PCM 缓存保留，松开立即停止采集，等待模型处理缓存；短按丢弃临时音频并释放麦克风，只打开会议面板。首次麦克风授权前浏览器无法采集，仍需先允许权限。键盘按住空格也可输入，Enter 打开会议面板。录制过程中可以关闭面板，底部状态条仍可结束录制，切换会话不会卸载录制控制器。

在“设置 → 语音与声纹”中自行选择会议模型。检测内存、逻辑核心数、进程架构和 NVIDIA 显存，推荐项排在第一位；推荐只改变排序，不自动下载或替换已经启用的模型。每个模型分别显示语言、用途、建议配置、下载大小、原版评测数据及来源。点击“下载安装并使用”，实际加载和解码验证成功后才启用；已安装模型可直接切换。录制过程中不能安装或切换。原有会议、全局声纹和可用的 SenseVoice 安装保留。

可选模型：Paraformer 中文 INT8（低配置优先，普通话）、SenseVoice Small INT8（中粤英日韩五语种）、Qwen3-ASR 0.6B INT8、Qwen3-ASR 1.7B（官方声明 30 种语言、22 类中文方言 / 口音）。0.6B 使用 sherpa-onnx 的 CPU ONNX 解码；1.7B 使用独立环境中的 qwen-asr / Transformers，并自动选择 CUDA、Apple MPS 或 CPU。1.7B 权重约 3.5 GB，另需约 2–5 GB 推理依赖。MPS 和其他系统的实际性能仍需实测，CPU 运行大模型可能跟不上录制。

纸面效果：SenseVoice 论文的同一对比表中，Paraformer-zh 的 AISHELL-1 / WenetSpeech meeting CER 为 1.95% / 6.97%，SenseVoice Small 为 2.96% / 7.44%。Qwen 官方报告自己的 meeting 评测中 0.6B / 1.7B 为 6.88% / 5.88%。不同报告的测试条件不能直接混排；这些数字不代表此处 INT8 包或用户录音的实测准确率。CER 为字符错误率。推荐配置是部署建议，不是经过各类硬件测定的实时性能保证。

## 本地模型

- 实时预览：[sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) 的 `sherpa-onnx-streaming-zipformer-zh-int8-2025-06-30`，中文流式识别，CPU 推理。预览文字尚未定稿，英文预览可能不完整。
- 最终转写：采用用户所选的 Paraformer、SenseVoice 或 Qwen3-ASR。每段结束后对 VAD 检出的实际音频重新识别，使用该结果保存会议逐字稿与生成纪要；64 位长按中文输入直接使用流式 Zipformer，避免加载会议模型。实时预览使用中文 Zipformer，不等于所选最终模型；其他语言以最终结果为准。32 位环境关闭预览节省内存。
- VAD：[Silero VAD](https://github.com/snakers4/silero-vad)，判断发言与静音，约 450 毫秒静音后提交一段文字；程序明确在连续发言约 12 秒时刷新并提交，防止一直积累预览。VAD 自身的 `max_speech_duration` 只调整切段阈值，不能保证强制切段。实时 ASR 仅接收检出的语音，包含起始预留音频；结束时通过 VAD 刷新尾句，纯静音不调用最终转写。
- 说话人：[3D-Speaker](https://github.com/modelscope/3D-Speaker) 的中英 CAM++ 声纹模型，使用约两秒声音窗口、每秒检测一次并确认新声纹。VAD 不负责区分身份。检测到换人后，对各人的声音分别转写；没有静音的换人也能检测。说话人编号按会议分别生成，用户可填写对应姓名、职务。

64 位环境的模型文件首次下载量约：Paraformer 391 MB、SenseVoice 328 MB、Qwen 0.6B 1041 MB、Qwen 1.7B 3662 MB，另需运行环境。32 位环境省略 133 MB 中文预览。共享 VAD、声纹和预览文件只需下载一次。安装时查询官方资源、检查大小，有官方 SHA-256 时同时核验。安装完成前实际加载并解码。首次安装需要访问 GitHub、PyPI、Python 发行下载地址；1.7B 还访问 Hugging Face 和 PyTorch。失败可重试，已完成的下载复用。运行中无需联网转写。

64 位安装路径覆盖 Windows 10+ x64、macOS / Linux x64 与 arm64。Windows 10+ 的 32 位桌面版可选择 Paraformer 或 SenseVoice，安装私有 CPython 3.11 x86、NumPy 1.26.4 与 sherpa-onnx 1.13.8 C API DLL，使用 ctypes 调用原生推理，不需要安装编译器或 32 位 sherpa Python wheel。Qwen 两个模型仅开放给 64 位；Windows ARM64 运行环境尚未集成。Windows 7 未验证，界面标为不可用。浏览器需要 HTTPS 或 localhost，以及 `MediaRecorder`、`AudioWorklet` 支持。

## 会议流程

1. 选择会议标题、会议记录角色（会议秘书、项目协调员、访谈记录员）。
2. 选择语音会议或视频会议。语音会议只采集麦克风；视频会议直接使用浏览器原生 `getDisplayMedia({ video: true, audio: true })` 选择窗口或屏幕，再使用 `getUserMedia` 接入麦克风，录制中显示共享画面预览。
3. 浏览器原生 `MediaRecorder` 保存音频或视频；Web Audio 将麦克风送入 AudioWorklet 转为 16 kHz 单声道 PCM。视频不会发给转写模型，结束后可在会议详情中直接预览回放。
4. 面板显示实时文字、发言状态和说话人。为说话人填写姓名与角色，会同步保存到本机。
5. 结束录制后刷新尾句，保存录制和逐字稿。默认将完整逐字稿作为附件发送给**当前配置的大模型**，在独立会话生成中文会议纪要；可关闭自动生成，手动生成或重新生成。
6. 从会议历史查看逐字稿、预览或下载录制、导出文本，也可以删除不需要的会议记录。纪要位于普通会话列表，可以继续追问。

不必提前添加参会人，也不必填写姓名；系统仍自动区分说话人 1、2、3。填写姓名和角色只影响当前会议。点击该说话人的“记住到全局”后，会将已采集的声纹及对应资料保存在本机全局声纹库；下次会议高置信匹配成功时自动填入姓名和角色，匹配不确定时仍使用编号。可在“设置 → 语音与声纹”或会议面板的“全局声纹配置”修改、删除记录。未明确保存的姓名不会成为全局身份。无需上传声纹，也不需要预先录制注册音频。

声纹匹配是估计，不能凭编号确定真实姓名。新声纹需至少两个相隔一秒的窗口相互匹配才生成编号，通常需要约三秒声音；过短或不确定的发言标为待确认。实时预览可以创建并切换新编号。整段 VAD 音频先按说话人分段，再分别转写，实时 ASR 不因换人判断而清空文字。全局身份匹配阈值为 0.65，并要求最佳候选比第二候选至少高 0.08；会议内匹配阈值为 0.48，新声纹两个窗口的匹配阈值为 0.55。只有高置信声音窗口才能更新已确认声纹，避免两个人的混合窗口把声纹拖到一起。此实现没有声源分离，需核对重叠发言和短暂插话。会议纪要提示词要求未知负责人、期限、身份和结论标为待确认，并引用发言时间。

共享音频支持取决于系统与浏览器；Electron 默认在 Windows 上请求 loopback，其他平台仍录制麦克风。是否已获得共享音频以系统的共享选项为准。

## 保存与恢复

模型环境保存在 `MLI_AGENT_DATA_DIR/local-speech/`；每次录制的数据位于 `MLI_AGENT_DATA_DIR/meetings/<uuid>/`，包含 `meeting.json` 和会议的浏览器原始 WebM / Ogg / MP4 文件。全局声纹库为 `MLI_AGENT_DATA_DIR/voice-profiles.json`。长按输入仅保存文字，不生成媒体文件，不列入会议历史。项目导出不包含会议内容、声纹库、模型或运行环境。

## 下载与删除

进度位于正在安装的模型卡片内，显示当前文件百分比、已下载、总大小、剩余大小、速度、预计时间与本次累计下载量。准备依赖、解压和验证阶段显示不定进度，不把未知大小显示成 0 B / 0 B。Qwen 1.7B 权重也走同一下载器。删除按钮移除该模型目录、归档、未完成下载和安装凭证；保留共享 VAD / 声纹 / 预览、推理环境及会议。删除当前模型自动选择其他可用模型，没有可用模型时需重新安装；录制或安装期间禁止删除。

模型和依赖由客户端直接下载，服务器不保存、不代理、不缓存 STT 文件。安装前会检查阿里云、腾讯云、华为云、HF 国内镜像、GitHub 加速源和官方回退源，逐文件显示源、速度、进度、校验和失败原因；客户端只下载当前系统和所选模型需要的资源。

权限默认值保存在应用数据目录的 `ui-preferences.json`；新建普通或专家会话继承该值。浏览器缓存仅用于首屏显示，后端记录保证桌面重启、端口变化后仍保留设置；历史会话维持自身模式。

录制文件按分片保存，上传重试不会重复追加。转写按序处理，结束时等待所有 PCM、录制分片和参会人修改保存完毕，再刷新尾句。保存失败时保留内存中的待上传分片，可点击“重试保存”。请勿在未完成保存时退出应用；关闭程序无法恢复尚未上传的分片。后端超过两分钟收不到数据会停止推理进程并将记录标记为已中断，已保存的文件和文字可从会议历史读取。

转写始终在本机，会议纪要使用所配置模型的协议和账户授权。生成纪要需要回到录制时的工作目录。完整逐字稿通过现有附件系统提供给模型，长会议要求模型分段读取全文。

## 验证

`npm run build:web`、`npm run check`、`npm test`。`test/speech.test.mjs` 覆盖录制生命周期、PCM 与媒体重试、尾句、角色映射、全局声纹保存/复用/修改/删除、逐字稿保存、纪要生成及工作目录约束。`test/speech-summary-http.test.mjs` 验证完整逐字稿、会议角色与实际模型会话的接入。`node node_modules/electron/cli.js test/fixtures/speech-browser-smoke.cjs` 在 Electron 中通过原生 AudioWorklet / MediaRecorder 验证浏览器录制流程和全局声纹按钮，使用合成音视频和模拟转写接口，不调用外部大模型。

真实模型回归使用插件环境的 Python 运行 `test/fixtures/speech-model-regression.py <local-speech目录> [16kHz单声道PCM16录音.wav]`。该检查不下载模型：验证静音不产生文字、官方中文样例的预览与最终转写、未满一个音频块的尾部保存，以及可选长录音的限时提交和不重复切段。可以通过 `--reference <wav>` 添加已知语音“我们今天讨论项目计划。请张三负责开发，李四负责测试，周五交付第一版。会议结束后生成会议纪要。”的逐字匹配验证。合成语音、官方样例和单次会议回放只验证对应场景，不能代表所有口音、噪声或多人同时说话的识别准确率。

`test/fixtures/speaker-model-regression.py <local-speech目录> [双人录音.wav]` 使用真实 CAM++ 验证两位说话人按 A-B-A 顺序发言后编号复用、单人音量变化不新增编号，以及可选会议的实时与最终双人分段。完整转写回归可添加 `--expected-speakers 2`，同时检查预览和保存的逐字稿都出现两个编号。
# 长按语音输入

长按期间将识别预览写入当前输入框，松开后更新为最终结果，不会打开会议弹窗。
64 位环境使用已安装的 Zipformer 中文流式识别器；长按不加载会议 STT 大模型或声纹模型。
会议仍使用设置中选择的模型。32 位环境使用所选轻量模型，断句后显示文字。
模型安装完成后，打开工作台、聚焦输入框、移到麦克风按钮或重新进入应用时会预热输入模型。预热不打开麦克风，只保留一个本地推理进程；加载阶段占用 CPU / 磁盘，加载后闲置主要占用内存。32 位轻量输入模型也可预热。预热中的进程可被输入会话直接接管，不另开一个进程重复加载。
浏览器音频处理链也提前准备，麦克风直接连接 AudioWorklet，避免中间音频流转接带来的启动空档。在已有麦克风授权的情况下，悬停或聚焦麦克风按钮会提前准备设备；未授权时不会因悬停弹出授权请求。首次授权或设备尚未启动时，界面显示“准备麦克风”，浏览器在设备就绪前无法取得音频。
语音输入结束后，PCM 采集立即暂停并确认尾部短分片，麦克风设备最多保留 15 秒，界面显示“麦克风待命”，可点击关闭。待命时不保存或发送音频，也不会把待命期间的声音带入下一段输入。空闲超时释放麦克风，音频处理链暂停后最多保留十分钟；切换项目、模型、离开应用或退出时释放闲置资源。会议录制结束仍直接释放全部录制设备。
加载完成或一次输入结束后保留十分钟，准备再次输入会更新空闲期限；长时间闲置自动关闭进程释放内存，下一次聚焦或使用时重新预热。切换 / 删除 / 安装模型和退出时释放。录制中的进程不受空闲缓存计时器影响。所有驻留模型都可通过状态接口查看 `dictation.state`、`resident` 和空闲期限。
首次冷启动仍需要加载本地模型，耗时取决于磁盘和 CPU；预热不代表识别结果已完成。麦克风按钮和底部状态显示旋转的加载反馈，模型未就绪不显示计时；PCM 在本机浏览器内缓存，松开停止采集并等待加载和尾句处理。模型就绪后才进入实时识别并从零开始显示计时。

缓存策略的回归为 `node --test test/speech-worker-cache.test.mjs`，包括加载中复用、闲置释放、输入期间不释放、异常重试。
麦克风生命周期回归为 `node --test test/dictation-microphone.test.mjs`。麦克风测试不能代表所有设备驱动的冷启动时间。
