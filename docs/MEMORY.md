# 记忆与经验沉淀

MLI Agent 的记忆不是训练模型，而是把用户偏好和有依据的项目经验保存到本地，在之后的任务中按需召回。记得更多适用的经验，才能减少重复说明和重复排错。

入口：**设置 → 记忆**。桌面、浏览器与终端共用运行时的记忆设置；旧版项目记忆会自动兼容读取，首次修改时转换为新版结构。

## 如何使用

### 多用户个人档案卡

开启“使用记忆”和“自动沉淀”后，每轮正常结束的真实模型对话会复用后台回顾请求，从用户明确自述中提取档案信息。没有档案时自动建立“当前使用者”卡，随后补充空字段；已有字段的不同值生成待确认建议，在设置中确认或忽略。启用“保存前审核”时，所有自动字段补充也先进入建议。每项保留用户原话、会话和消息位置；不以助手自报或工具结果作为个人资料证据。自动识别第三人、假设和引文依赖模型判断，原话校验只能验证出处，不能保证语义归属完全正确，用户仍可纠正。

设置中的“个人档案卡”支持在同一账户下维护多张使用者档案，并选择当前使用者。档案包含称呼、职责、团队、负责事项、目标、专长、工作偏好和协作方式；每次任务开始时只将当前档案的摘要冻结到提示词，子 Agent 继承同一份快照。每张档案拥有独立的全局偏好记忆空间，切换档案不会读取或写入上一位使用者的偏好；项目事实仍按工作区共享。未登录时使用本机档案，登录后按账户 ID 隔离。档案最多 50 张，字段经过长度限制和凭据脱敏。

当前账户服务只提供个人/企业主体和团队知识，没有公开的成员档案读写接口，因此企业成员档案同步尚未接入；本地档案不会冒充已认证的企业成员资料。后续接入时应将成员档案放在企业主体命名空间，按成员权限下发，并保留本地档案作为离线缓存。

- **使用记忆**：控制正文注入、记忆工具和后台沉淀。关闭后已有条目保留，仍可在设置中管理；再次打开继续使用。
- **自动沉淀经验**：开启时，Agent 可以在任务中保存稳定信息，根任务成功完成后还会用当前模型进行一次后台回顾；关闭后停止后台回顾，提示 Agent 只在用户明确要求记住、更新或忘记时修改记忆。
- **保存前审核**：Agent 新增内容先进入「待审核」，通过后才用于召回。后台回顾提出的替换始终待审核，绑定原记忆版本，避免覆盖用户之后的修改。前台写入仍遵守普通工具权限。
- **允许检索历史会话**：允许 Agent 按关键词检索当前项目过去的根会话消息，返回会话与消息位置；不会自动把全部聊天放进上下文。

这四项设置默认开启，只有「保存前审核」默认关闭。后台回顾会额外调用真实模型并产生相应 token 用量，调用记录可在模型的调用分析中查看。mock 演示模型不会自动生成记忆。

可以这样交流：

> 记住：以后用中文，先报告结果，再说明关键验证。
>
> 这个项目使用 pnpm，测试完成后运行 pnpm build，请记住这个验证流程。
>
> 上次的排错方法不适用了，请更新那条记忆。

在记忆库中可以搜索、按范围/类型/状态筛选，查看并编辑正文、标签、依据，优先召回、停用、审核或删除。保留最近 10 个编辑版本，恢复时生成新版本；删除会同时移除该条目的版本历史。Agent 保存和自动回顾的条目保留来源会话，后台条目还记录证据消息位置。

停用条目和待审核条目不会用于召回。编辑在下一轮重新召回时生效；当前轮使用固定快照，避免工具步骤之间不断改变提示。总开关即时阻止新的记忆工具调用、提示注入与回顾写入，但无法抹去此前已经出现在当前对话中的内容。

## 分层与召回

**全局记忆**适合用户沟通偏好与跨项目工作习惯，保存到运行时用户数据目录的 `memories/memory.json`，切换工作区后仍可使用。不同用户数据目录相互隔离。

**项目记忆**适合稳定事实、排错经验与可复用方法，保存到当前项目 `.agent/memory.json`。子 Agent 共享主任务所属项目的记忆，不随临时执行目录改变；子 Agent 可以读取，但不能自行写长期记忆。后台回顾只在根任务成功完成后启动，子任务汇报不会被直接当作成功证据。

正文根据置顶、全局偏好和当前任务相关性筛选：最多 8 条、每条最多 1100 字符，总正文块预算 4400 字符；另保留最多 24 条其他标题、2200 字符的目录。排序采用本地 BM25 风格词频与语料稀有度，标题和标签权重高于正文；再结合置顶、用户确认、时间衰减和真实召回次数。`search_memories` 使用同一相关性排序检索有效记忆。该实现不需要网络或 embedding 服务；中英文分词仍为轻量字符/词项切分，不等同于语义向量召回。召回次数统计注入或工具读取次数，并不表示模型必然采用了该记忆。

历史检索采用本地中英文关键词匹配，与长期记忆分开。每次最多扫描最近 100 个根会话、每个文件末尾 1 MiB、总计 8 MiB，返回最多 20 条消息片段。长历史的早期内容可能未被扫描；这一版没有向量数据库、embedding 或语义搜索。

## 后台如何学习

成功结束的根任务进入单并发后台队列，不阻塞任务结果展示。回顾输入限定为本轮真实用户消息、成功工具结果和已有记忆摘要，过滤助手自称成功、协作汇总以及记忆工具的循环反馈。

每次最多提出 3 条新记忆，内容应明确适用条件、稳定结论或可复用步骤。每条必须引用真实记录中的原句并附消息 ID；跨项目用户偏好必须由用户原话支持。替换已有主题会生成待审核提案，原记忆保持有效。工作流程保存为方法记忆，不自动生成可执行 Skill。

回顾限时 20 秒，输出最多 1800 tokens。关闭开关、编辑记忆或中断运行会使过期结果失效；失败仅记录在「学习记录」，不把已成功的任务改成失败。进度保存在项目 `.agent/memory-learning.json`，保留最近 40 次；重启后未完成的回顾标为中断，不盲目重新执行。

引用校验能阻止没有出处的写入，但不能证明模型的概括完全正确。对重要的经验建议开启保存前审核；在使用中纠正、合并或停用不适用的条目。常见凭据格式会脱敏，这不是对所有秘密格式的完整识别。

## 数据与开发

项目存储兼容旧数组，新格式为 `{ "version": 2, "items": [...] }`。条目包含范围、类型、状态、依据、来源、版本、历史与召回统计。全局最多 200 条，项目最多 500 条；满库时提示整理，不静默丢弃旧记忆。

写入使用进程锁、临时文件和原子替换；修改、删除、审核、恢复需要 `expectedRevision`，过期版本返回 HTTP 409。损坏的数据不会被空数组覆盖；拒绝符号链接越过所属范围。

配置示例：

```json
"memory": {
  "enabled": true,
  "autoLearn": true,
  "reviewBeforeSave": false,
  "historyEnabled": true
}
```

管理 API：`/api/memory/settings`、`/api/memory/learning`、`/api/memories`、`/api/memories/:scope/:id`，审核与恢复分别使用 `POST .../approve`、`POST .../restore`。编辑 `PUT` 与删除 `DELETE` 都要提交读取时的版本。

验证：`node --test test/memory*.test.mjs` 检查隔离、版本、审核、开关、提炼和 HTTP 完整链路；`npm run build:web` 后用 `node node_modules/electron/cli.js scripts/verify-memory-ui.cjs` 检查真实页面的管理操作和桌面/手机布局。后者启动独立临时运行时，不修改当前工作区记忆。自动提炼测试使用本地模拟接口和可控适配器，没有对真实模型进行长期效果评测。
