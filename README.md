# 魔力工作台 · MLI Agent

把想法做成文件，而不只是一段回答。

魔力工作台是一款本地运行、面向资料整理、文档办公、开发与写作的 Agent 工作台。你提出目标，它读取项目资料、选择工具、执行操作，再根据结果继续处理。文稿、网页、表格和素材保存在自己的工作目录里，可以检查、修改和继续使用。

客户端包含 React 工作台、Node.js Agent 运行时、Electron 桌面入口，以及插件与 Skill 系统。**不依赖官方账户后台即可使用自带模型服务；账户、支付、官方模型网关、管理后台和官网不在客户端开源范围内。**

[GitHub 源码](https://github.com/ponysb/mlimli) · [问题反馈](https://github.com/ponysb/mlimli/issues) · [Apache-2.0 许可证](LICENSE)

## 为什么是工作台，而不只是聊天窗口

- **能落到文件。** 读取、创建、编辑项目文件，运行命令，把模型建议变成可继续使用的成果。
- **过程可以看见。** 展示模型输出、工具调用、审批与执行结果，以及任务耗时、token 和缓存用量；不用猜它正在做什么。
- **长任务可以接着做。** 会话以本地追加记录保存，支持切换项目、导入旧会话、排队消息和上下文压缩；历史记录不会因压缩而直接删除。
- **模型可以自己选。** 支持 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 协议，可配置多服务商、多模型和自己的 API Key。
- **工作方法可以扩展。** 写作专家提供叙事方法，Skill 提供任务流程，插件提供执行工具；不把所有能力锁在同一段提示词里。
- **授权由你决定。** 默认人工审批，写入、普通命令和敏感工具按规则确认；需要时可切换完全访问模式，桌面控制还需单独开启。

这些是已实现的客户端能力，不代表模型总能一次完成任务。输出质量、工具调用与多模态能力取决于实际模型，重要成果仍需核验。

## Agent 是怎样工作的

一次任务不是把提示词发出去就结束，而是一个“生成 → 执行 → 反馈”的循环：

```text
用户目标 + 附件
       ↓
读取当前会话、项目约定、专家方法与可用技能索引
       ↓
检查上下文预算，必要时生成结构化摘要
       ↓
向当前模型发送上下文与工具定义，接收流式输出
       ↓
模型请求工具？ ── 否 → 保存最终回答和任务摘要
       │ 是
       ↓
执行前钩子 → 权限审批 → 执行工具 → 执行后钩子
       ↓
保存工具结果，回传给模型，进入下一轮
```

### 1. 组装与任务有关的上下文

运行时结合系统规则、工作目录环境、项目 `AGENTS.md`、当前专家方法、技能索引和项目记忆索引。技能与记忆由工具按需读取，不会把全部资料固定塞进每次请求。参考材料和工具输出不应替代用户当前要求。

### 2. 模型决定下一步，客户端负责执行

模型返回文字或工具调用。客户端组装流式工具参数，找到对应工具，经授权后实际执行，再把结果写回会话。执行失败也会作为结果反馈给模型，供其调整后续操作。没有工具调用时，这轮任务结束；用户可随时停止正在运行的任务。

工具由本地内核与插件注册，包括文件读写、命令执行、网页读取、资源库、项目记忆、Office、媒体和桌面操作。它们不是模拟聊天里的“已完成”文案。

### 3. 用会话树保留过程，用摘要控制上下文

消息、工具结果、步骤、审批和任务结束事件追加到工作目录的 `.agent/` 中。发送给模型的是选取后的上下文窗口，而不是每次无限回放全部历史。

达到配置的上下文阈值时，运行时通过模型生成目标、决定、文件、命令、工具、待办与风险等结构化摘要，作为新的压缩记录保存。默认阈值为配置上下文窗口的 75%；token 占用是估算值，并非供应商精确计数。摘要可能遗漏信息，必要时应重新读取原始文件。

### 4. 通过事件把执行过程送回界面

浏览器界面以 REST 提交操作，通过 SSE 接收模型片段、工具事件、权限请求、运行状态和任务摘要。React 负责呈现，`server.mjs` 与 `core/` 负责本地执行；Electron 为同一客户端提供桌面窗口与原生文件选择。

## 可以做什么

### 写作与故事创作

- 内置多种写作方法专家，覆盖故事定位、开篇、节奏、人物、世界观、章节钩子等。
- 新建故事、整理设定、设计章节细纲、续写与修改文稿。
- 创建自己的专家与 Skill，保存在项目内；专家是提示方法，不是后台训练的独立模型，也不是自动并行子 Agent。

### 网站与代码项目

- 浏览工作区文件，读取与编辑代码、创建页面、执行开发命令。
- 用集成编辑器查看文本与代码，用预览入口检查支持的成果格式。
- 借助网页开发技能拆解任务；数据库、部署、第三方服务仍需用户配置和授权。

### 文档、数据与媒体

- Office 插件提供 DOCX、XLSX、PPTX 的读取、部分编辑与生成；不是完整 Office 排版引擎。
- Office 格式转换需要系统上的 Microsoft Office 或 LibreOffice，具体能力以平台和安装环境为准。
- FFmpeg 插件支持媒体探测、转码、裁剪、拼接、音轨提取与缩略图，需要另行安装 FFmpeg。
- 资源库保存图片、音频、视频等素材；生成媒体需要相应服务、模型或工具，不内置免费的生成后端。

### 工作区与任务管理

- 多工作目录、项目会话、文件树与文本编辑。
- 消息排队、运行中补充调整、取消执行、任务摘要和旧会话导入。
- 项目记忆、素材管理与调用分析，包含输入、输出、缓存读取、缓存创建和本地费用估算。
- 配置官方服务时，账户相关额度使用魔力值；自带模型服务由其供应商结算，本地估算不是账单。

### 扩展与桌面操作

- 支持本地 `plugin.json` 与 `.codex-plugin/plugin.json` 插件、Skill、命令和执行钩子。
- 内置轻量 stdio MCP 桥，提供工具搜索、描述和调用；并非所有 MCP 传输方式都兼容。
- Windows 桌面插件可截图、读取窗口与 UIA 控件、聚焦窗口、点击和输入；需要显式开启桌面会话。
- 附带的第三方工作流 Skill 不代表相应 App/OAuth 已经接通。GitHub、Notion、Linear 等连接需要另行实现或配置与授权。

## 快速开始

### 环境

使用 **Node.js 22.12 或更新版本**，建议 Node.js 24。当前前端构建依赖不支持只安装 Node.js 18 的完整安装流程。Windows 是桌面自动化的主要环境；其他平台可使用兼容的核心与 Web 工作台，但并非所有插件都可用。

### 安装和运行

在客户端源码目录执行：

```sh
git clone https://github.com/ponysb/mlimli.git
cd mlimli
npm ci
```

首次使用复制安全示例配置。PowerShell：

```powershell
Copy-Item config.example.json config.json
```

macOS / Linux：

```sh
cp config.example.json config.json
```

已有 `config.json` 时不要覆盖。然后构建并启动：

```sh
npm run build:web
npm start
```

打开 `http://127.0.0.1:3000`。示例默认使用 **mock 演示模型**、关闭官方账户要求，便于不提供 Key 跑通界面与审批流程；它不是真实 AI。可在新的工作目录中输入“写一个 hello.txt”，观察工具调用与写入审批。

接入真实模型：在设置里新增服务商，选择协议，填写 API 地址与 API Key，再添加或选择模型。API 地址通常包含 `/v1`，实际以供应商为准。真实 Key 属于本地私有配置，不要分享或提交到公开仓库。

**自带模型使用不需要启动 `server/`，不需要数据库、管理员账号或官方支付服务。** 推荐先选择专门的项目工作目录，不要把包含私有后台的混合开发目录交给 Agent 当作公开示例。

### Electron 桌面窗口

前端构建完成后执行：

```sh
npm run electron
```

Electron 会启动使用独立回环端口的本地服务并打开工作台，无需手动启动第二个服务，也不会占用源码版的 3000 端口。桌面数据独立保存在 `%APPDATA%/MoliCreation/`，首次运行使用安全的 mock 演示配置，不导入开发者凭据或聊天记录。

Windows 一键打包两版：`npm run dist:win`（`npm run dist:win:all` 也可）。自动构建、验证现代版与兼容版，`release/` 直接保存两份最新安装包和 SHA-256 校验文件，中间文件自动清理，不再生成时间戳目录。需要免安装版时执行 `npm run dist:win -- --portable`。现代版（Win10/11 x64）单独执行 `npm run dist:win:modern`，旧系统兼容版（Electron 22 / ia32，目标 Win7 SP1 和 Win10 32 位）执行 `npm run dist:win:legacy`。兼容版使用独立数据目录，旧运行时已停止安全维护，需补充目标系统真机或虚拟机测试。仅生成现代调试解包目录：`npm run pack:win`。安装包只包含客户端，不包含私有后台和官网。完整流程与验证命令见 [Windows 打包说明](docs/WINDOWS-PACKAGING.md)。

### 客户端环境配置

源码 `npm start` 和 `npm run electron` 都会自动读取项目根目录 `.env`，无需手动设置系统环境变量；已有进程环境变量优先。可从 `.env.example` 创建自己的 `.env`，不要覆盖已有文件。配置公开账户后台时使用：

```dotenv
MLI_ACCOUNT_SERVER_URL=https://你的后台域名
MLI_ACCOUNT_ENABLED=true
MLI_AGENT_PORT=3000
```

修改后重启客户端。这里配置客户端连接地址；`server/.env` 是私有后台的数据库、JWT、支付等配置，客户端不会读取它。不要在客户端分发服务端共享密钥。Windows 打包自动提取上述公开字段，不复制私有 `.env` 或其他密钥；安装后覆盖配置及升级行为见 [Windows 打包说明](docs/WINDOWS-PACKAGING.md)。客户端开源导出只带安全 `.env.example`，不带你的地址配置或凭据。

### 前端开发与验证

```sh
npm run dev:web
npm test
npm run check
```

`dev:web` 仅启动前端开发服务器，不会自动代理本地 API；完整功能以构建后由 `npm start` 托管的页面为准。测试与自检覆盖客户端的会话、权限、文件、模型协议等逻辑，不等于真实供应商、支付或桌面应用的端到端验证。

## 安全与数据边界

- 默认服务绑定 `127.0.0.1`。本地服务具有文件和命令执行能力，不应直接暴露到公网或当作多人 SaaS 后端。
- 人工审批下，只读工具与受限的只读查询可自动执行；写文件、其他命令和敏感工具需要按权限策略确认。完全访问模式自动放行一般写入和命令，但不会自动解锁桌面敏感工具。
- 文件工具有工作目录边界，但 shell、插件和外部程序并不是操作系统级沙箱。不要运行不可信插件或在有重要未备份资料的目录里随意授权。
- “本地保存”不等于“完全离线”：调用外部模型、网页或插件时，任务相关上下文可能发给对应服务；mock 模式则只用于本地演示。
- 项目会话、记忆与日志可能含源码、文件路径、个人资料和模型输出。账户会话另存于操作系统用户配置目录，不要把这些数据随开源包发布。
- 不提交 `config.json`、`.env`、Key、Token、支付/数据库配置或 `.agent/`。客户端发布包不得携带服务端共享密钥；官方托管计费应由私有网关服务端结算。

## 客户端源码结构

```text
server.mjs          本地 HTTP / SSE 服务，是客户端运行时的一部分
core/               Agent 循环、模型协议、会话、权限、记忆和资源
react/              React 工作台及品牌素材
plugins/            本地插件与第三方工作流 Skill
electron/           Electron 入口、预加载脚本与图标
scripts/            自检与客户端导出工具
test/               客户端回归测试
config.example.json 无凭据、无个人路径的启动示例
```

## 客户端开源，服务端保持私有

本项目采用“**公开客户端仓库 + 私有服务仓库**”的代码边界：完整客户端公开，不把 `server/` 账户后台及其内的 `server/website/` 官网一起发布。这里的 `server.mjs` 是本地客户端入口，与私有 `server/` 目录不是同一个东西。

在内部工作目录生成独立发布目录：

```sh
npm run export:client -- --dry-run
npm run export:client
```

默认输出 `release/client-source/`。导出使用明确白名单，并生成文件 SHA-256 清单；不复制内部运行配置、会话、日志、历史 Git 数据或官网与后台代码，且移除依赖私有后台的 npm 脚本。不要直接在内部混合目录执行 `git add .` 后推到公共仓库。

导出是**生成发布候选源码**，不是自动上传或完成许可证审核。公开客户端仓库为 [ponysb/mlimli](https://github.com/ponysb/mlimli)。首次发布、后续同步和第三方许可核对见 [客户端开源方案](docs/OPEN-SOURCE.md)。
